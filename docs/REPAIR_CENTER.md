# مركز الإصلاح

## مبدأ الأمان

لا يقبل مركز الإصلاح نص command أو PowerShell أو executable أو argument من الواجهة. كل عملية تُعرَّف داخلياً بمعرّف ثابت ومواصفة مجمدة. يحتاج التطبيق إلى تأكيد المستخدم لكل عملية إدارية، ويطلب elevation عند التنفيذ الحقيقي فقط؛ لا يعمل التطبيق كله بصلاحيات administrator.

## العمليات المعتمدة

| المعرّف | الغرض | ملاحظة |
|---|---|---|
| `repair-dism-check-health` | قراءة حالة Windows component store | يسمح dry-run. |
| `repair-dism-scan-health` | فحص component store | يسمح dry-run. |
| `repair-dism-restore-health` | طلب استعادة component store | قد يغير النظام؛ لا يشغله الاختبار الحي. |
| `repair-sfc-verify-only` | تحقق SFC | يسمح dry-run. |
| `repair-sfc-scan-now` | فحص وإصلاح SFC | قد يغير النظام؛ لا يشغله الاختبار الحي. |
| `repair-dns-flush` | مسح DNS cache | يحتاج تأكيد. |
| `repair-winsock-reset` | إعادة Winsock | قد يتطلب إعادة تشغيل. |
| `repair-tcpip-reset` | إعادة TCP/IP | قد يتطلب إعادة تشغيل. |

## dry-run

تعرض dry-run قدرة العملية المسموح بها والنتيجة المخططة من دون تشغيل UAC أو الأمر الإصلاحي. تتحقق الحزمة من dry-run للعمليات الثمانية؛ لا يعني ذلك أن إصلاحاً حياً مناسب لكل جهاز.

## قبل التنفيذ الحقيقي

راجع الأثر والقيود، وأغلق العمل الحساس، وتحقق من وجود نسخة احتياطية مناسبة. لا تشغّل إصلاحات شبكة أو component store لمجرد وجود تحذير عام. إذا فشل elevation أو لم تكن العملية متاحة، يعرض التطبيق نتيجة منظمة ولا يحاول بديل shell عام.

## الخدمات

أدوات الخدمات مستقلة عن مركز الإصلاح. تميز الجرد الخدمات المحمية والقابلة للتحكم وغير المعروفة. لا يتيح التطبيق action لمجرد أن خدمة موجودة، ويقيد actions ومخطط الاسم وقائمة الحماية. اختبارات الحزمة تستخدم جرداً وdry-run فقط لتجنب تغيير خدمة حي في جهاز الاختبار.
