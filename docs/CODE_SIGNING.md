# توقيع الشفرة لـ KNOuX SmartOrganizer

## السياسة

ينتج المشروع حالتين صادقتين فقط:

| الحالة | المعنى |
|---|---|
| `SIGNED_PRODUCTION` | جميع قطع الإصدار المحددة تملك توقيع Authenticode صالحاً وفق Windows. |
| `UNSIGNED_PRODUCTION_CANDIDATE` | لا توجد شهادة موثوقة مهيأة أو لم يتحقق توقيع صالح. يمكن بناء القطعة واختبارها، لكنها ليست ادعاءً بتوزيع تجاري موقع. |

> **توقيع صالح لا يساوي سمعة SmartScreen.** لا يضمن توقيع Authenticode ظهور التطبيق بلا تحذير SmartScreen، ولا يعرض التطبيق ادعاء «SmartScreen trusted».

## ما يجب ألا يدخل المستودع

لا تلتزم مطلقاً بأي من العناصر التالية:

- ملف `.pfx` أو `.p12` أو `.pem` أو `.key`.
- كلمة مرور شهادة أو token أو شهادة base64 أو مفتاح خاص.
- نسخ من مخرجات أو أسرار مزود التوقيع.

تفحص `scripts/verify-release.cjs` امتدادات المفاتيح ومؤشرات المفتاح الخاص وبيانات الاعتماد المضمنة داخل المصدر، وتفشل البوابة عند العثور عليها.

## إعداد البناء الموقع

يتعامل electron-builder مع بيانات اعتماد Windows القياسية من بيئة البناء. يجب توفيرها في مدير أسرار موثوق أو في بيئة بناء محلية مؤقتة فقط، وليس في `package.json` أو ملف مصدر.

| بيئة مطلوبة عند استخدام electron-builder القياسي | الغرض |
|---|---|
| `CSC_LINK` | موقع شهادة Authenticode أو مرجعها المعتمد في بيئة البناء. |
| `CSC_KEY_PASSWORD` | كلمة مرور الشهادة عندما يلزمها ذلك. |
| `KNOUX_REQUIRE_SIGNING=1` | يطلب أن يرفض التحقق النهائي القطع غير الموقعة. |

في CI، توضع القيم في GitHub Actions Secrets وتُمرر إلى خطوة البناء فقط. لا تسجل محتواها ولا تطبعها في logs.

## البناء والتحقق

```powershell
npm ci
npm run desktop:dist
npm run signing:verify
```

يحفظ `npm run signing:verify` الدليل في `docs/evidence/code-signing.json`. ويقرأ لكل من المثبّت والملف التنفيذي:

- `Status` من `Get-AuthenticodeSignature`.
- موضوع شهادة الموقّع، إن وجد.
- موضوع شهادة الطابع الزمني، إن وجد.
- خوارزمية توقيع الشهادة، إن وجدت.

لإلزام توقيع صالح في قناة إصدار تملك شهادة موثوقة:

```powershell
$env:KNOUX_REQUIRE_SIGNING = '1'
npm run signing:verify
```

إذا لم تكن هناك شهادة موثوقة، يظل المسار الصحيح هو تسجيل `UNSIGNED_PRODUCTION_CANDIDATE` واعتبار شهادة التوقيع حاجز توزيع خارجي، بدلاً من اختراع شهادة أو وصف القطعة بالموقعة.

## النطاق

يجب أن يغطي التوقيع عند توفره مثبّت NSIS، والملف التنفيذي الرئيسي، وأي helper تنفيذي يجمعه electron-builder. يجري التحقق على القطع النهائية فقط بعد آخر build؛ أي إعادة بناء تستلزم إعادة حساب البصمات وإعادة التحقق.
